# DayUp

DayUp 是一个供自己使用的本地工作生活工作台，在电脑浏览器中统一管理计划、工作、学习和生活记录。无需账号、云数据库或部署，应用运行时不依赖互联网。

## 一、解决什么问题

当工作任务、学习笔记、健身和饮食记录分散在不同地方时，很难快速知道今天该做什么、哪些事需要跟进，以及之前记录了什么。DayUp 用首页“今日驾驶舱”集中展示重点、时间线和摘要，再由各模块记录各自需要的细节。

今日计划负责“准备做什么”，开发日志、学习时长、训练和餐食记录负责“实际做了什么”；两者分开记录，避免把完成计划当成实际学习或训练数据。笔记支持文字、代码和截图，便于长期积累知识。

## 二、主要功能

| 页面 | 主要功能 |
| --- | --- |
| 首页总览 | 最多三件今日重点、需要关注的事项、今日时间线、快速备忘、各模块摘要 |
| 今日计划 | 过去及未来日期、全天/待安排/具体时间、优先级、每日/每周/每月重复、提醒、完成/取消/推迟/删除 |
| 开发工作 | 项目详情、任务看板、问题、里程碑、开发日志；任务安排到计划后完成状态双向同步 |
| 咨询工作 | 客户信息、沟通记录、待跟进事项 |
| 学习空间 | 今日学习任务、可往返拖放的学习日历、科目书架、历史笔记、章节进度和实际学习时长 |
| 健身计划 | 健身目标、训练日历、多个训练部位和动作、组数/次数/重量、实际训练记录 |
| 饮食计划 | 饮食日历、餐食、热量、蛋白质和饮水记录 |
| 游戏娱乐 | 游戏库、游玩记录 |
| 数据与设置 | JSON 备份与恢复、查看备份文件夹、选择删除备份、清空本地数据、通知及外观设置 |

学习笔记包含文字、代码和截图内容块，支持自动保存、正文/标签搜索、代码语言选择、基础高亮、原文复制和下载。图片可以上传、粘贴或拖入；内容块可整卡拖动排序，输入区保留文字编辑，也可用把手或上移/下移按钮。

应用提供马卡龙、玻璃、硬边三套外观。代码仅保存和展示，不执行；不包含自媒体模块、登录、云同步、多人协作、OCR 或外部 AI 服务。

## 三、安装方法

### 运行条件

- 使用电脑浏览器。Windows 可使用根目录的启动脚本，并通过资源管理器查看备份文件夹。
- 安装可在终端运行的 Python 3，使用 `python --version` 确认是否可用。若找不到命令，需先安装 Python 3 并配置其命令路径。
- 日常运行不需要 Node.js、npm 安装或前端构建，也不需要下载第三方 Python 包；服务使用 Python 标准库，前端文件已位于 `dist/`。

### 获取并启动

1. 将整个项目文件夹保存在电脑上，至少保留 `server.py`、`dist/` 和启动脚本，不要只复制网页文件。
2. 在 Windows 双击根目录的 `start-dayup.bat`，会启动本地服务并打开默认浏览器。
3. 默认访问 `http://localhost:4173/`。重复启动时，如果该端口已经运行 DayUp，会复用现有服务。

也可以在项目根目录的终端运行：

```powershell
python server.py --open
```

若日常数据已在其他端口，例如当前的 `http://localhost:4183/`，请继续使用这个地址，并按相应端口启动：

```powershell
python server.py --port 4183 --open
```

服务只监听本机回环地址。手动在终端启动时，可在该终端按 `Ctrl+C` 停止服务；再次启动并使用原浏览器与原地址即可继续读取已保存的数据。修改 `server.py` 后需要重启服务，修改前端文件后刷新页面。

## 四、使用方法

### 每日计划与各模块

1. 首页查看今日重点、需要关注和时间线；临时想法可放进快速备忘，也可将备忘转换成计划。
2. 新建计划时填写名称、所属模块、日期和时间。优先级、重复、提醒和重点位于“更多设置”。日期可完整输入 `YYYY-MM-DD` 或用主题日历选择；时间面板可选择小时和分钟，也可选全天或待安排。
3. 完成后勾选任务。重点每天最多三件；重复计划可选择只修改本次或本次及以后。每月重复按原始日号计算，短月使用当月最后一天。
4. 进入相关模块记录实际结果。开发项目可拆任务、记问题与日志；咨询记录沟通和跟进；健身、饮食通过日历记录每天的实际情况；游戏记录游玩情况。各模块均可单独使用。

### 学习空间与笔记

1. 点击侧栏“学习空间”进入学习首页。今日任务只突出名称、计划时间和完成方框；完成时出现对号与笔触划线。
2. 把任务拖到日历日期可重新安排。日历里的每条任务可继续拖到其他日期，也可拖回顶部今日计划或“拖回今日计划”区域。重复任务仅移动本次；也可通过编辑日期调整安排。
3. 点击“进入笔记书屋”。新建笔记本即添加科目，数学、Python 等都可以；原有科目会自动显示在书架上。悬停或聚焦笔记本会产生抽书效果。
4. 打开笔记本后查看历史标题、创建笔记或搜索。编辑科目、安排计划、章节、进度和时长记录统一放在默认折叠的“学习管理”中。
5. 新建笔记可选择知识点、代码练习或问题排查模板，再添加文字、代码、截图。离开前确认显示“已保存”；保存失败会保留编辑器草稿，可重试“保存笔记”。

截图支持 PNG/JPEG/WebP，单张最多 5MB，解码后最多 4000 万像素，每篇最多 100 个内容块。代码保留空白和缩进；语言面板支持方向键、回车和 Escape。截图原字节随笔记保存到备份中。

### 本地数据、备份与恢复

日常数据保存在当前浏览器的本地存储中，主存储不可用时尝试本地数据库。刷新、关闭页面后重开仍可读取已保存数据。日常数据不会自动写成项目目录中的 JSON 文件，`backups/` 是手动导出的快照。

请使用同一浏览器和同一地址，包括端口。`localhost:4173`、`localhost:4183`、`127.0.0.1`、直接打开 `dist/index.html` 的 `file://` 地址，以及不同浏览器，均不会自动共享数据。更换入口前先导出备份，再在新入口导入。清除浏览器站点数据会影响本地记录，请定期备份。

- **导出备份**：通过本地服务运行时，自动在项目根目录创建 `backups/`，保存按北京时间命名的 JSON；同一天多份不覆盖。文件备份上限为 100MB，写入失败会提示错误。
- **查看备份文件夹**：请求 Windows 资源管理器打开该文件夹。
- **导入备份**：默认列出该文件夹中的历史备份；选定文件、校验并确认后覆盖当前数据。“从其他位置导入”可选择自行保存的 JSON。旧版备份仍兼容。
- **删除备份**：选择一份或多份历史文件，确认后删除所选文件，不清空正在使用的数据。

建议通过本地服务使用。直接双击 `dist/index.html` 时，导出改为浏览器下载，不能获得相同的项目文件夹管理能力。备份包含个人记录、代码及截图，请自行妥善保管。

### 提醒与外观

在“数据与设置”点击“启用通知 / 测试提醒”，允许浏览器通知并保持页面打开。已完成、已取消的计划不提醒；关闭整个浏览器后没有后台提醒。

侧栏和设置页可切换三套外观，选择保存在当前浏览器。快捷键为 `Ctrl / ⌘ + Shift + T`；若浏览器占用该快捷键，请用按钮。`http://localhost:4173/styleguide.html` 为独立样式参考页；自定义端口时替换其中的端口。该页试写内容不保存。

## 五、输入输出示例

### 示例 1：创建一条学习计划

在“今日计划”新建计划，填写下表并保存：

<!-- example:plan -->
| 输入字段 | 输入值 |
| --- | --- |
| 计划名称 | 复习 Python 列表 |
| 所属模块 | 学习空间 |
| 日期 | 2026-11-02 |
| 时间 | 09:30 |
| 优先级 | 普通 |
| 重复 | 不重复 |
| 提醒 | 不提醒 |

**输出结果**：选择 `2026-11-02` 后能看到“复习 Python 列表”，时间为 `09:30`；学习日历的相应日期也能查看这条任务。勾选完成后，两处的完成状态同步。刷新后仍保留该任务和完成状态。

### 示例 2：保存带缩进的代码笔记

在书屋创建“Python”笔记本，新建“遍历列表”笔记，选择“代码练习”模板，在代码块中选择 `python` 并输入：

<!-- example:code -->
```python
numbers = [1, 2, 3]
for number in numbers:
    print(number * 2)
```

**输出结果**：保存后显示“已保存”。返回笔记本、重新打开或刷新后，原始换行和四个空格缩进保留；阅读预览显示代码，复制或下载得到原文。应用不会运行代码，也不会产生执行结果。

### 示例 3：导出与恢复备份

**输入操作**：在“数据与设置”点击“导出备份”。

**输出文件示例**：

```text
backups/dayup-backup-2026-10-30_120000_123456.json
```

实际日期与时间取导出时的北京时间，末尾数字用于区分多份备份。文件包含当前计划、项目、各模块记录及笔记截图等数据。之后在“导入备份”中选择该文件，校验并确认后恢复该快照；快照导出之后新增的内容不会自动合并。

## 测试与开发依据

### 准备公开源码

公开前可在根目录运行：

```powershell
python tools/prepare_public.py
```

程序只按允许清单收集源码、文档和固定测试样例，检查常见凭据、邮箱、硬编码绝对路径及版权署名；通过后生成 `release/DayUp-public.zip`。压缩包包含相对路径与 SHA-256 清单 `PUBLIC-MANIFEST.json`，不包含 Git 历史、内部协作约定、本地备份、验收截图、测试输出、编译缓存或环境配置。扫描失败会报告文件与行号，不打印敏感值，也不会生成新的发布包。

这是源码分发包，解压后按照前面的安装方法运行；不会上传 GitHub，也不会删除本地数据。公开时使用检查后的源码包，不要直接上传整个工作目录或推送未经检查的旧 Git 历史。旧历史仍可能包含以前的作者身份或旧文件；此导出流程不读取或修改历史。自动检查覆盖常见格式，公开前仍需人工审阅自由文本内容。

运行测试需要 Node.js 和 Python，不需要安装 npm 依赖。在项目根目录执行任一命令：

```powershell
npm test
```

```powershell
node tools/run-tests.mjs
```

测试覆盖本地服务、数据保存与恢复、各模块行为和交互回归；README 中的计划与代码示例也有对应行为测试。结果保存在 `test-results/summary.json`、`test-results/node-tests.tap` 和 `test-results/python-tests.log`。浏览器验收记录和截图也位于 `test-results/`；自动测试不能代替实际页面验收。
